## 🎯 What Changed?

### Problem trước đây:
- Frontend có hardcoded 4 predefined messages
- User phải **hold button** để record → Không intuitive
- Mỗi lần record → **INSERT mới vào database** → Duplicate records vô tận
- Không check xem message đã có audio chưa → User không biết phải record hay không

### Solution mới:
- ✅ Frontend **fetch từ database** (`quick_responses` table)
- ✅ UI mới: **Click để chọn** → **Button riêng để record** → **Upload & save**
- ✅ **UPDATE** thay vì INSERT → Không duplicate
- ✅ **Hiển thị status**: Có audio (✅) / Chưa có audio (🎤 Chưa ghi âm)
- ✅ **Validate**: Chỉ cho send nếu đã có audio_url

## 🔄 Complete Workflow

### 1️⃣ User opens AudioMessageControl:
```
Frontend → GET /api/quick-responses
         ← [{ id: 1, title: "wait", audio_url: "...", is_active: true }, ...]
```

### 2️⃣ User selects "Vui lòng đợi" (title: "wait"):
```
- Display: "Tin nhắn: Vui lòng đợi"
- Check audio_url:
  - If empty → Show "🎤 Chưa ghi âm" badge + "Ghi âm mới" button enabled
  - If exists → Show "✅" badge + "Phát tin nhắn này qua loa" button enabled
```

### 3️⃣ User clicks "Ghi âm mới":
```javascript
navigator.mediaDevices.getUserMedia({ audio: true })
→ Record audio → Stop → Blob created
→ Show audio player + "Lưu ghi âm này" button
```

### 4️⃣ User clicks "Lưu ghi âm này":
```
Frontend → uploadAudio(blob, "wait_1735567000.wav")
         → Supabase Storage (bell-audio bucket)
         ← audio_url

Frontend → PATCH /api/quick-responses/wait
           Body: { audio_url: "https://...bell-audio/wait_1735567000.wav" }
         ← { success: true, data: { id: 3, title: "wait", audio_url: "...", ... } }

Frontend → Refresh quick responses list
```

### 5️⃣ User clicks "Phát tin nhắn này qua loa":
```
Frontend → POST /api/commands/speak
           Body: { audio_url: "https://...wait_1735567000.wav", volume: 80 }
         ← { success: true, command_id: "cmd_...", ... }

Node-RED → MQTT Publish to "doorbell/cmd/speak"
           Payload: { command_id: "...", audio_url: "...", volume: 80, timestamp: ... }

ESP32    ← MQTT Subscribe "doorbell/cmd/speak"
         → Download audio from URL
         → Play audio via speaker
```

## 🗄️ Database Schema (No Changes Needed)

Table `quick_responses` đã tồn tại:
```sql
CREATE TABLE public.quick_responses (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    created_at timestamp with time zone DEFAULT timezone('utc'::text, now()),
    title text NOT NULL,
    audio_url text NOT NULL,
    is_active boolean DEFAULT true
);
```

**Current Records:**
```sql
INSERT INTO quick_responses (title, audio_url, is_active) VALUES
('wait', '', true),
('notHome', '', true),
('busy', '', true),
('package', '', true);
```

**Title Mapping:**
- `wait` → "Vui lòng đợi" (⏰)
- `notHome` → "Tôi không có nhà" (🏠)
- `busy` → "Tôi đang bận" (📵)
- `package` → "Để hàng ở cửa" (📦)
