### Step 1.3: Create Database Schema

1. Vào **SQL Editor** (icon ⚡) trong Supabase dashboard
2. Click **"+ New query"**
3. **Copy và chạy script này:**

```sql
-- ============================================
-- DOORBELL SYSTEM DATABASE SCHEMA
-- ============================================

-- 1. EVENTS TABLE
CREATE TABLE public.events (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    created_at timestamp with time zone DEFAULT timezone('utc'::text, now()) NOT NULL,
    event_type text NOT NULL CHECK (event_type IN ('button_press', 'motion_detected', 'snapshot')),
    image_url text,
    images text[],
    description text NOT NULL,
    is_read boolean DEFAULT false,
    metadata jsonb
);

-- Indexes for events
CREATE INDEX idx_events_created_at ON public.events(created_at DESC);
CREATE INDEX idx_events_type ON public.events(event_type);
CREATE INDEX idx_events_unread ON public.events(is_read) WHERE is_read = false;

-- 2. VOICE NOTES TABLE
CREATE TABLE public.voice_notes (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    created_at timestamp with time zone DEFAULT timezone('utc'::text, now()) NOT NULL,
    audio_url text NOT NULL,
    duration_seconds int CHECK (duration_seconds > 0 AND duration_seconds <= 60),
    transcription text,
    is_listened boolean DEFAULT false,
    metadata jsonb
);

-- Indexes for voice_notes
CREATE INDEX idx_voice_created_at ON public.voice_notes(created_at DESC);
CREATE INDEX idx_voice_unlistened ON public.voice_notes(is_listened) WHERE is_listened = false;

-- 3. SENSOR LOGS TABLE
CREATE TABLE public.sensor_logs (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    created_at timestamp with time zone DEFAULT timezone('utc'::text, now()) NOT NULL,
    sensor_type text DEFAULT 'temperature' CHECK (sensor_type IN ('temperature', 'humidity')),
    temperature float CHECK (temperature >= -40 AND temperature <= 80),
    humidity float CHECK (humidity >= 0 AND humidity <= 100),
    metadata jsonb
);

-- Indexes for sensor_logs
CREATE INDEX idx_sensor_created_at ON public.sensor_logs(created_at DESC);
CREATE INDEX idx_sensor_type ON public.sensor_logs(sensor_type);

-- 4. DEVICE SETTINGS TABLE (Singleton)
CREATE TABLE public.device_settings (
    id int PRIMARY KEY DEFAULT 1 CHECK (id = 1),
    updated_at timestamp with time zone DEFAULT timezone('utc'::text, now()) NOT NULL,
    alarm_enabled boolean DEFAULT false,
    do_not_disturb boolean DEFAULT false,
    speaker_volume int DEFAULT 80 CHECK (speaker_volume >= 0 AND speaker_volume <= 100),
    pir_enabled boolean DEFAULT true,
    notifications_enabled boolean DEFAULT true,
    firmware_version text,
    last_sync timestamp with time zone,
    metadata jsonb
);

-- Trigger to auto-update updated_at
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = timezone('utc'::text, now());
    RETURN NEW;
END;
$$ language 'plpgsql';

CREATE TRIGGER update_device_settings_updated_at 
BEFORE UPDATE ON device_settings
FOR EACH ROW EXECUTE FUNCTION update_updated_at_column();

-- Insert default settings
INSERT INTO public.device_settings (id, alarm_enabled, speaker_volume, pir_enabled, notifications_enabled)
VALUES (1, false, 80, true, true)
ON CONFLICT (id) DO NOTHING;

-- ============================================
-- ROW LEVEL SECURITY (RLS)
-- ============================================

-- Enable RLS on all tables
ALTER TABLE public.events ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.voice_notes ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.sensor_logs ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.device_settings ENABLE ROW LEVEL SECURITY;

-- Allow authenticated users full access (Node-RED + Frontend users)
CREATE POLICY "Allow authenticated access" ON public.events
FOR ALL USING (auth.role() = 'authenticated');

CREATE POLICY "Allow authenticated access" ON public.voice_notes
FOR ALL USING (auth.role() = 'authenticated');

CREATE POLICY "Allow authenticated access" ON public.sensor_logs
FOR ALL USING (auth.role() = 'authenticated');

CREATE POLICY "Allow authenticated access" ON public.device_settings
FOR ALL USING (auth.role() = 'authenticated');

-- Allow service_role to bypass RLS (Node-RED với service_role key)
CREATE POLICY "Service role bypass" ON public.events
FOR ALL USING (auth.jwt() ->> 'role' = 'service_role');

CREATE POLICY "Service role bypass" ON public.voice_notes
FOR ALL USING (auth.jwt() ->> 'role' = 'service_role');

CREATE POLICY "Service role bypass" ON public.sensor_logs
FOR ALL USING (auth.jwt() ->> 'role' = 'service_role');

CREATE POLICY "Service role bypass" ON public.device_settings
FOR ALL USING (auth.jwt() ->> 'role' = 'service_role');
```

4. Click **"Run"** (hoặc Ctrl+Enter)
5. Kiểm tra **"Success"** message
6. Vào **Table Editor** để xem các tables đã được tạo

### Step 1.4: Create Storage Buckets

#### Bucket 1: bell-images

1. Vào **Storage** (icon 🗂️) trong sidebar
2. Click **"New bucket"**
3. **Cấu hình:**
   - Name: `bell-images`
   - Public bucket: ✅ **Check** (cho phép public access)
   - File size limit: `5 MB`
   - Allowed MIME types: `image/jpeg, image/jpg, image/png`
4. Click **"Create bucket"**
5. Vào bucket vừa tạo → **Policies** tab
6. Click **"New policy"**
7. **Policy cho public read:**
   - Policy name: `Public read access`
   - Operation: `SELECT`
   - Template: `Allow public read access`
   - Target roles: `public`
8. Click **"Review"** → **"Save policy"**
9. **Policy cho authenticated upload:**
   - Policy name: `Authenticated upload`
   - Operation: `INSERT`
   - Target roles: `authenticated`
   - Check: `(bucket_id = 'bell-images')`
10. Click **"Review"** → **"Save policy"**

#### Bucket 2: bell-audio

Làm tương tự với `bell-images`:

1. Click **"New bucket"**
2. **Cấu hình:**
   - Name: `bell-audio`
   - Public bucket: ✅ **Check**
   - File size limit: `10 MB`
   - Allowed MIME types: `audio/wav, audio/mp3, audio/mpeg`
3. Create **2 policies** giống như trên (public read + authenticated upload)

```json

  ],
  "allowedMethods": ["GET", "POST", "PUT", "DELETE"],
  "allowedHeaders": ["*"],
  "maxAgeSeconds": 3600
}
```

3. Click **"Save"**

### Step 3.3: Create Supabase Client

```javascript
import { createClient } from '@supabase/supabase-js';

const supabaseUrl = import.meta.env.VITE_SUPABASE_URL;
const supabaseAnonKey = import.meta.env.VITE_SUPABASE_ANON_KEY;

export const supabase = createClient(supabaseUrl, supabaseAnonKey);

// Helper functions
export const uploadImage = async (file, path) => {
  const { data, error } = await supabase.storage
    .from('bell-images')
    .upload(path, file, {
      cacheControl: '3600',
      upsert: false
    });
  
  if (error) throw error;
  
  // Get public URL
  const { data: { publicUrl } } = supabase.storage
    .from('bell-images')
    .getPublicUrl(path);
  
  return publicUrl;
};

export const uploadAudio = async (file, path) => {
  const { data, error } = await supabase.storage
    .from('bell-audio')
    .upload(path, file);
  
  if (error) throw error;
  
  const { data: { publicUrl } } = supabase.storage
    .from('bell-audio')
    .getPublicUrl(path);
  
  return publicUrl;
};
```

### Step 3.4: Create API Client

Tạo file `src/lib/api.js`:

```javascript
import axios from 'axios';

const API_BASE = import.meta.env.VITE_API_BASE_URL;

const api = axios.create({
  baseURL: API_BASE,
  headers: {
    'Content-Type': 'application/json'
  }
});

// Events API
export const getEvents = async (params = {}) => {
  const response = await api.get('/events', { params });
  return response.data;
};

export const markEventRead = async (eventId) => {
  const response = await api.patch(`/events/${eventId}/read`);
  return response.data;
};

// Voice Notes API
export const getVoiceNotes = async (params = {}) => {
  const response = await api.get('/voice-notes', { params });
  return response.data;
};

// Sensor Logs API
export const getSensorLogs = async (hours = 24) => {
  const response = await api.get('/sensor-logs', { params: { hours } });
  return response.data;
};

export const getLatestSensor = async () => {
  const response = await api.get('/sensor-logs/latest');
  return response.data;
};

// Settings API
export const getSettings = async () => {
  const response = await api.get('/settings');
  return response.data;
};

export const updateSettings = async (settings) => {
  const response = await api.patch('/settings', settings);
  return response.data;
};

// Commands API
export const takeSnapshot = async () => {
  const response = await api.post('/commands/snapshot');
  return response.data;
};

export const sendAudioMessage = async (audioUrl, volume = 80) => {
  const response = await api.post('/commands/speak', {
    audio_url: audioUrl,
    volume
  });
  return response.data;
};

export const toggleSiren = async (action, duration = 5) => {
  const response = await api.post('/commands/siren', {
    action,
    duration
  });
  return response.data;
};

export default api;
```

## 6. Troubleshooting

### Issue 1: CORS Error trong Frontend

**Lỗi:** `Access to XMLHttpRequest... has been blocked by CORS policy`

**Fix:**
1. Check Node-RED settings.js đã enable CORS chưa
2. Restart Node-RED sau khi sửa settings
3. Kiểm tra frontend `.env` có đúng URL không

### Issue 2: Supabase RLS Error

**Lỗi:** `new row violates row-level security policy`

**Fix:**
1. Vào Supabase → **Authentication** → **Policies**
2. Check policies đã được tạo chưa
3. Hoặc tạm thời disable RLS (chỉ khi dev):
   ```sql
   ALTER TABLE events DISABLE ROW LEVEL SECURITY;
   ```

### Issue 3: MQTT Connection Failed

**Lỗi:** `Failed to connect to MQTT broker`

**Fix:**
1. Check HiveMQ credentials
2. Check firewall có block port 8883 không
3. Check ESP32 WiFi connected chưa
4. Test với MQTT Explorer trước

### Issue 4: Upload Failed (413 Payload Too Large)

**Fix:**
1. Check file size limit trong Supabase Storage settings
2. Compress ảnh/audio trước khi upload
3. Tăng limit trong bucket settings

### Issue 5: Node-RED Flow không chạy

**Fix:**
1. Check tất cả nodes đã được config (không có tam giác đỏ)
2. Click **Deploy** sau mỗi thay đổi
3. Check Debug panel có error messages
4. Restart Node-RED
